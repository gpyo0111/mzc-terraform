## 카드 1. S3 퍼블릭 액세스 전면 차단

**흐름:** 누가 버킷을 "전체 공개"로 만들려 함(퍼블릭 ACL/정책 `Principal:*`) → **퍼블릭 차단 4종이 무효화/거부** → 외부에서 못 봄.

**무엇 (4종 전부 ON):**
- `block_public_acls` — 새 퍼블릭 ACL 차단
- `ignore_public_acls` — 기존 퍼블릭 ACL 무시
- `block_public_policy` — 새 퍼블릭 버킷 정책 차단
- `restrict_public_buckets` — 퍼블릭 정책 가진 버킷 접근 제한
- → ACL 2개 + 버킷정책 2개 = 모든 퍼블릭 경로 봉쇄

**왜:** 음성(생체정보) 버킷 실수 노출 = 최악 → 사람이 잘못 써도 계정/버킷 레벨에서 강제 차단(안전망).

**어디:** audio/model/web-static/tf-state + cloudtrail-logs/flow-logs/athena-results.

**❓ 드릴 (보지 말고 말로):**
- Q1. 퍼블릭 차단 4종을 ACL용·정책용으로 나누면? 왜 둘 다 필요?
- Q2. 버킷정책으로 CloudFront는 허용했는데, 퍼블릭 차단이랑 안 부딪히나?
- Q3. 이게 막는 "최악의 사고"는 구체적으로 뭔가?

**💡 모범답안:**
- A1. ACL용 2개(새 퍼블릭 ACL 차단 + 기존 무시), 정책용 2개(새 퍼블릭 정책 차단 + 퍼블릭 버킷 접근 제한). 퍼블릭으로 여는 경로가 ACL·정책 두 가지라 둘 다 막아야 완전.
- A2. 안 부딪힘. 퍼블릭 차단은 `Principal:*`(누구나)인 것만 막음. CloudFront는 특정 서비스 + SourceArn 조건이라 '퍼블릭'이 아님 → 통과. (문지기 정책 + 퍼블릭 차단 안전망 = 이중 방어)
- A3. 사용자 음성 원본(생체정보) S3 버킷이 인터넷에 통째로 노출되는 사고. 개인정보 유출 + 컴플라이언스 위반.

## 카드 2. S3 등급별 수명주기 정책

**흐름:** 음성 업로드 → 등급별 폴더(`uploads/guest|free|tenants/`) 저장 → S3가 매일 객체 나이 체크 →
- guest: 7일 → 삭제
- free: 30일 → Glacier → 90일 삭제
- paid(tenants): 30일 → Glacier → 365일 삭제
- (uploads/ · results/ 각각)

**왜:** ① 비용(오래된 음성 싸게/삭제) ② 생체정보 최소보관(유출면 축소·컴플라이언스).

**용어:** Glacier = 콜드 스토리지(아주 싸게 장기보관, 꺼낼 때 시간·비용).

**❓ 드릴 (보지 말고 말로):**
- Q1. guest 음성은 며칠 뒤 어떻게? 왜 유료보다 짧게?
- Q2. "수명주기가 보안이랑 무슨 상관? 비용절감 아닌가?" 반박에 답?
- Q3. Glacier로 "이동"하는 이유? 그냥 삭제하면 안 되나?

**💡 모범답안:**
- A1. 7일 뒤 즉시 영구 삭제. guest는 체험/임시라 보관 가치 낮고 빨리 파기, 유료는 서비스 가치상 오래 보관.
- A2. 보안과 직결됨. **생체정보는 보관 자체가 위험**(들고 있는 동안 유출·오남용 가능). 최소 기간만 보관 = 유출면(공격 표면) 축소 + 개인정보보호 컴플라이언스. 비용은 부수효과.
- A3. 삭제 의무 기간 전(유료 365일 등)엔 보관해야 하므로, 그 기간 동안은 **자주 안 쓰는 데이터를 싼 Glacier로 옮겨 비용 절감**. 보관 의무가 끝나면 삭제.

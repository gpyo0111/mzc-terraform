# SecureVoice 보안 발표 PPT 개편 지시서 (21장 → 17장)

> **목적:** 기존 발표 PPT가 "설정 화면 캡처 나열"이라 단조롭고 김(예방만 7장).
> 캡처를 증거용으로만 줄이고, 같은 메시지 슬라이드를 합쳐 **21장 → 17장**, 발표 ~25분 → ~15분으로.
> 이 문서만 보고 새 슬라이드 구성을 만들 수 있게 자체완결로 작성함.

## 0. 프로젝트 한 줄 배경 (맥락)
- **SecureVoice** = 음성(=생체정보) 처리 서비스. 그 **AWS 인프라 보안**을 `pmg-security` 레이어에서 **Terraform(IaC)** 로 전담 구축.
- 계정 dev 단일 · 서울(ap-northeast-2) + 글로벌(us-east-1) 2리전 · 운영 중 무중단.
- 발표 서사 = **보안 생애주기 6단계: 예방 → 경계 → 탐지 → 알림 → 자동대응 → 운영.**

## 1. 캡처(스크린샷) 원칙 — "안 믿길 것에만 증거로"
- ✅ **리치하게 유지:** KMS 키정책 JSON / WAF가 CloudFront에 실제 Enabled / **자동대응 데모(수신 이메일 + before-after + Lambda 로그)**.
- 🔽 **축소(칩·체크표시·문구 한 줄로):** S3 퍼블릭 차단 4종 토글, 수명주기 규칙 6개 목록, worker SG "규칙 없음".
- 🔁 지루한 "설정 화면"은 가능하면 **"결과/before-after"** 컷으로 대체.

## 2. ⚠️ 공개 시 마스킹 필수
계정ID(455535733131) · CloudFront ID · KMS 키 ARN · GuardDuty Detector ID · 버킷명/도메인 → **외부 공개(블로그/깃허브/제출)면 흐리게.** 사내 발표면 그대로 OK.

## 3. 순서 교정
기존에 "6단계 개요"가 예방 1/7과 2/7 **사이**에 끼어 있었음 → **예방 시작 전(아키텍처 뒤)** 으로 이동.

## 3-1. ⚠️ 알림 파이프라인(신규 그림) ↔ 구 17 "알림·자동대응 아키텍처" 중복 조율
- 새로 넣은 **알림 파이프라인 그림**(사건 3갈래 → EventBridge·CloudWatch → SNS → 이메일)이 **구 17 아키텍처 슬라이드의 흐름 설명과 겹침.**
- **조율:** 파이프라인 그림이 흐름(개념)을 다 담당 → **구 17은 그림/흐름 부분 삭제**하고, 파이프라인엔 없는 **"증거 리스트"만** 남김:
  - **EventBridge 규칙 8종 목록** (글로벌 us-east-1 4종: root-account-usage·iam-sensitive-changes·guardduty-findings·access-analyzer-findings / 서울 4종: sg-rule-changes·cloudtrail-tampering·guardduty-findings·access-analyzer-findings)
  - **자동대응 Lambda 2종** (sg-auto-remediate · cloudtrail-auto-recover)
- 또는 구 17을 **아예 삭제**하고 위 증거 리스트를 **파이프라인 슬라이드 하단에 작게** 붙여도 됨.
- ※ SG 자동회수 데모(14·15)와는 겹치지 않음(데모는 실제 발동 사례라 별개).

## 4-1. Athena 트러블슈팅 슬라이드 쿼리(캡처 예시)
```sql
SELECT eventtime, useridentity.arn AS who, eventname, requestparameters
FROM cloudtrail_logs
WHERE eventname IN ('AuthorizeSecurityGroupIngress','ModifySecurityGroupRules')
  AND requestparameters LIKE '%0.0.0.0/0%'
  AND year='2026' AND month='07'   -- 파티션으로 스캔 범위 축소(비용)
ORDER BY eventtime DESC;
```

## 5. 요약
- **예방 7→4, 탐지 3→2**, 6단계 개요 위치 교정, 알림에 파이프라인 그림 추가.
- **운영(구 20) 슬라이드 삭제 → Athena 0.0.0.0/0 추적 트러블슈팅으로 대체.** 운영의 판단력 2줄은 마무리(17)로 이사(내용 보존).
- **13(알림 파이프라인) = 알림 담당 / 14~15(SG 데모) = 자동대응 담당**으로 역할 분리(흐름 재설명 중복 제거). 기존 17(아키텍처)은 파이프라인과 중복이라 축소/삭제.
- **21장 → 17장.** 더 줄이려면 예방④(9)를 예방③(8)에 흡수 → 16장.
- 캡처는 **KMS 키정책 · WAF Enabled · 자동대응 데모 · Athena 추적결과** 만 리치하게, 나머지는 축소.

## 6. (선택) 여유되면 추가하면 강해지는 슬라이드 2장
> 기존 목차에 "그림자 리소스 추적/ISMS-P"를 적어놨으나 본문에 없었음. 시간 되면 트러블슈팅 파트로 추가 권장.
- **A. 그림자 리소스 30초 추적:** 정체불명 SageMaker 버킷을 CloudTrail+Athena로 추적→본인 콘솔클릭이 원인 확인→삭제. (탐지 인프라 실사용 증명)
- **B. WAF "만든 것 ≠ 적용된 것":** 코드로 만든 WAF가 아니라 CloudFront 무료플랜 자동WAF가 붙어있던 것 발견→플랜취소→IaC WAF로 교체. (IaC 함정 진단)
